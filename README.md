# zt-web

Личный некоммерческий сайт с обзорами и тестами заточных камней, станков и
расходников. WordPress на VPS через Docker Compose.

Спека итерации — в `openspec/changes/bootstrap-vps-wordpress/`; решения с
обоснованиями и разобранными альтернативами — в её `design.md`. Читать до
любой работы по инфраструктуре: половина решений неочевидна.

## Из чего состоит стек

| Сервис      | Образ                          | Роль                                          |
|-------------|--------------------------------|-----------------------------------------------|
| `caddy`     | `caddy:2.11.4-alpine`          | приём 80/443, сертификаты, редирект на HTTPS  |
| `wordpress` | `wordpress:7.0.2-php8.3-apache`| сайт и админка                                |
| `db`        | `mariadb:11.8.8-noble`         | база данных, порт наружу не публикуется       |
| `wpcli`     | `wordpress:cli-2.12.0-php8.3`  | служебный, профиль `tools`: плагины, роли     |

Наружу публикуются только 80 и 443. База доступна лишь по внутренней сети
контейнеров.

## Раскладка

```
docker-compose.yml            стек сервера
docker-compose.local.yml      надстройка для локальной копии
Caddyfile                     обратный прокси, режимы IP и домена
plugins.txt                   декларативный список плагинов, slug==версия
.env.example                  полный перечень переменных с назначением
config/
  apache/zt-mpm.conf          число рабочих процессов
  mariadb/zt-tuning.cnf       параметры базы под малую память
  php/zt-php.ini.template     пределы загрузки и памяти, из окружения
  wordpress/wp-config-zt.php  адрес сайта, работа за прокси, запрет правки файлов
wp-content/
  mu-plugins/zt-guardrails.php  обработка изображений, права ролей, индексация
  themes/zt-web/                тема (появится в итерации вёрстки)
scripts/                      подготовка хоста, деплой, откат, бэкап, плагины, роли
deploy/cron/zt-web            расписание бэкапа
docs/                         процедуры, ограничения, уступки тестовой машине
openspec/                     спеки
```

## Что где живёт

- **В git:** конфигурация стека, свой код, скрипты, спеки.
- **В томах на сервере, вне git:** ядро WordPress, сторонние плагины, загрузки
  (`wp-core`), база данных (`db-data`), сертификаты (`caddy-data`).
- **На сервере, вне git:** `.env` с секретами, права 600.
- **В Backblaze B2:** дампы базы. Копий медиа нет — см.
  [docs/limitations.md](docs/limitations.md).

Обновление кода не затрагивает состояние, а удаление рабочей копии не приводит
к потере данных: они в томах, а не в каталоге.

## Быстрый старт

Сервер и все процедуры — [docs/runbook.md](docs/runbook.md).

Локальная копия для разработки:

```bash
cp .env.example .env && chmod 600 .env
./scripts/gen-secrets.sh          # значения скопировать в .env
./scripts/local-up.sh             # http://localhost:8080
ZT_LOCAL=1 ./scripts/wp-provision.sh
```

## Роли — разные люди

**Редактор** пишет статьи и загружает фотографии, работая только через
веб-админку: штатная роль `editor`, ни SSH, ни репозитория, ни секретов.
**Разработчик** владеет репозиторием, сервером и деплоем.

Встроенный редактор файлов темы и плагинов отключён для всех, включая
администратора: код попадает на сервер только через репозиторий.

## Сервер не пустой

На тестовом VPS работает **Amnezia (AmneziaWG, UDP 43421)**. Её нельзя ломать.
Отсюда: ufw не включается, правила пакетного фильтра не трогаются, Docker не
переустанавливается. После любого изменения, затрагивающего сеть, проверяется
**и** сайт, **и** VPN-подключение — второе из первого не следует.
